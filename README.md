# Лист — учебный интернет-магазин (версия 2)

Новый независимый проект. Содержит каталог товаров, корзину, регистрацию и вход, оформление заказов, историю покупок и API для управления товарами.

## Быстрый запуск: БЕЗ Docker, PostgreSQL и установки пакетов

Требуется только Node.js 20 или новее (у вас уже установлен Node.js 22).

1. Распакуйте `shopp.zip`.
2. Откройте **папку `shopp`** в VS Code.
3. В терминале PowerShell выполните **`node server.js`**.
4. Откройте **http://127.0.0.1:3000**.

**Важно:** старый проект `north-shop` запускать не нужно. Docker Desktop также не нужен. Если в старом терминале продолжает работать `npm.cmd run dev`, остановите его через `Ctrl+C`.

Сервер автоматически создаёт `data/shop.json` из `data/seed.json` при первом старте. В нём хранятся товары, пользователи и заказы. Это учебное файловое хранилище, а не промышленная СУБД. Чтобы сбросить проект, **остановите сервер** и удалите только `data/shop.json` (потеряются тестовые регистрации/заказы).

## Проверка

- Главная страница: http://127.0.0.1:3000
- API Health: http://127.0.0.1:3000/api/health — `{ "ok": true }`
- API каталога: http://127.0.0.1:3000/api/products — JSON с 8 товарами
- Автоматические API-тесты: `node --test tests/api.test.js`

## Соответствие техническому заданию

- Product: название, цена, категория, наличие, остаток.
- Order: позиции и количество, итоговая сумма, статус, владелец.
- Публичный каталог товаров и фильтрация по категории.
- Регистрация/вход с JWT, хранение хеша пароля с scrypt.
- API продуктов: `GET /api/products`, `GET /api/products/:id`, `POST /api/products`, `PUT /api/products/:id`, `DELETE /api/products/:id`.
- API заказов: `POST /api/orders`, `GET /api/orders`, защищённые JWT.
- Сумма заказа и наличие проверяются на сервере; только свои заказы; ответы 401/403.
- Корзина, каталог, история заказов, регистрация и вход в интерфейсе.

### Панель администратора

Для входа зарегистрируйтесь на сайте с вашим email. В терминале проекта выполните:

```powershell
node make-admin.js your-email@example.com
```

Подставьте email созданного аккаунта. После назначения роли выйдите из аккаунта и войдите снова. В верхнем меню появится **«Админ-панель»**.

В панели доступны обзор показателей, добавление, редактирование и удаление товаров, изменение цен и остатков, выбор фотографий из восьми встроенных изображений. В разделе **«Заказы»** — список всех заказов и изменение их статусов. Все действия проверяются на сервере по JWT и роли администратора.

Для просмотра данных без прав администратора сервер возвращает 401 либо 403. Информация о покупателях не доступна посетителям каталога.

## React + TypeScript (для контрольной точки)

В папке `react-client` есть **отдельный полноценный React + TypeScript интерфейс** с Axios interceptor, роутингом по состоянию и защищёнными функциями. Его можно использовать вместо готовой HTML-версии при оценивании по контрольной точке.

1. В терминале №1 из корневой папки `shopp` запустите `node server.js`.
2. Во втором терминале выполните `cd react-client`.
3. Выполните `npm.cmd install` (только React-версия требует скачивания зависимостей).
4. Выполните `npm.cmd run dev`.
5. Откройте http://127.0.0.1:5173.

Vite проксирует `/api` на `http://127.0.0.1:3000`. Адрес можно изменить в переменной `VITE_API_URL` (пример `.env.example`). Код Axios interceptor — в `react-client/src/main.tsx`.

React-версия зависит от скачивания пакетов из npm и отдельно отрабатывается сборкой `npm.cmd run build`. Основная HTML-версия работает без установки пакетов.

## Сценарий для защиты

1. Показать каталог без входа и фильтр категорий.
2. Добавить пару товаров в корзину и изменить количество.
3. Нажать «Оформить заказ» без входа — переадресация на регистрацию/вход.
4. Зарегистрироваться и оформить заказ.
5. Открыть историю заказов.
6. В новой вкладке проверить `/api/products` и `/api/health`.
7. Показать запрос без JWT к `/api/orders` → HTTP 401.

## Ограничения

Учебная реализация: нет онлайн-оплаты, доставки, рассылки и публикации в интернет. JSON-хранилище не рассчитано на параллельную запись большой нагрузки; для коммерческого магазина понадобится SQL-база и транзакции. JWT_SECRET задан по умолчанию только для локального запуска; при публикации необходимо задать надёжный секрет через переменную окружения.
